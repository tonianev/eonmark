# H3: Render watchdog on cold CI runners

Size S · Risk low · Lane R · Waits on: a second stall (conditional)

## Goal
Only if `game compiles on Linux` fails again with `render_watchdog: render pipeline ... not ready after 20 s` and one `worst_ms` near 20000 (seen once, on PR #57, and green on its re-run): make the 20 s threshold configurable and set 60 s in CI's render smoke only. Never remove the watchdog or its ERROR gate.

## Anchors
- `crates/game/src/render_watchdog.rs`: `not ready after`
- `scripts/render_smoke.sh`: `ERROR`
- `.github/workflows/ci.yml`: `render_smoke`

## Steps
1. Read the threshold constant in `render_watchdog.rs` and add `EONMARK_RENDER_WATCHDOG_S` (default 20, parsed once at startup, a bad value falls back to 20 with a `warn!`).
2. In ci.yml's game-linux job set the variable to 60 for the render-smoke steps only.
3. Document it in IMPLEMENTER_NOTES's "A WGSL error is logged, not fatal" row.

## Tests
`the_threshold_defaults_to_20_seconds`, `a_valid_override_is_used`, `a_bad_override_falls_back_to_the_default`.

## Verify
`cargo test -p game --profile ci render_watchdog`; CI green.

## Done when
The default is still 20 and CI's smoke tolerates a slow runner.
