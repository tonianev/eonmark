# M6-1: Ingest the fun-gate matches

Size S · Risk low · Lane S · Waits on: owner session O1 (docs/PLAN.md)

## Goal
The owner's three streamed matches are logged in PLAYTEST with verified replays, every threshold is evaluated, and the lines O1 covers are ready for the owner's tick.

## Serves
M6 line 6 (the owner ticks it) and M5b's [owner] line (PLAN D6).

## Anchors
- `docs/PLAYTEST.md`: `Match log (M6)`, `Fun gate thresholds (M6)`
- `crates/sim-cli/src/match_log.rs`: `match-log`

## Steps
1. Read the owner's session issue (title `Owner session YYYY-MM-DD: O1`). Put the three `match_log:` rows into PLAYTEST "Match log (M6)" as iteration 0, keeping the owner's Fun and Notes verbatim.
2. If replays are attached, commit them under `docs/playtest/replays/` (new directory, about 40 KB each) and run `cargo run -p sim-cli --release --locked -- verify <file>` on each: it must print `OK final_hash=<the row's hash>`. Verify with a build of the commit the row names (`rules_version` and `SIM_VERSION` must match). If they are not attached, the owner's `just match-log` output with `OK 0x...` is the evidence.
3. Evaluate each row of "Fun gate thresholds (M6)": pass or fail, naming the cell that decides it. A match under 20 or over 40 minutes fails the duration row; "AI reached my borders" and "Town below 50% HP" must hold in at least 2 of 3; the Yield Cap readout must have turned amber at least once per match; Fun at least 3 of 5.
4. All pass: tick M5b's [owner] line if the issue marks it `pass` (PLAYBOOK P3). Put the exact tick text for M6 line 6 in the PR description and ask the owner to apply it. An agent never ticks the fun gate. Mark M6-3 `ready`.
5. Any fail: list the failed criteria and the owner's notes in the PR, and mark M6-2 `ready`.

## Verify
`python3 -I scripts/check_roadmap_ticks.py origin/main` prints ok; CI green.

## Done when
Rows and verification are in PLAYTEST, and the board points to M6-2 or M6-3.

## Stop if
A replay does not verify with the recording build: that is a determinism bug, not a tuning input. Open a `needs-design` issue with the replay and the two hashes.
