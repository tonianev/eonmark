## Facts (verified 2026-11-08)
- `Sim::step` runs 1 queue, 2 AI think, 3 apply, 4 pathing, 5 movement and combat (5b' attrition, 5c hits, 5d annexation), 6 economy (construction, training, jobs, income, bonus, then `victory::step`), then `self.state.tick += 1`. The new step 7 goes after `victory::step`, immediately before `tick += 1`: the grid reflects the tick's final positions.
- `Sim::hash()` is xxh3 over the postcard of the whole `State`: adding a `visibility` field to `State` changes every total hash by itself. `SubHashes` is separate: add `visibility: u64` (a tenth name), update `NAMES` (`[&str; 9]` becomes 10), `values()` (`[u64; 9]`), `first_difference` and `sub_hashes()`, and every test that counts the names.
- `Sim::new` builds `State { ... }` then `town::apply_standard_start`. Stamp once at the end of `new` (after the standard start) so the grid is valid at tick 0 and the initial hash already contains it.
- `MatchSetup` fields append at the end, with the `SIM_VERSION` bump making the replay reader fail fast on old files. Literal `MatchSetup { .. }` appears only in `state.rs`; every other site uses the constructors above.

## Session 1: fog
1. Branch from `origin/main`. Bump `SIM_VERSION` (`crates/sim/src/state.rs`) and `rules_version` (`data/rules/rules.ron`). The PR stays a draft until session 2 ends; every later commit re-records without bumping again.
2. `visibility.rs`: `VisibilityGrid { width, height, players: Vec<Vec<u8>> }` with serde, `new`, `step(&mut State, &Rules)`: for each player, decay every state 2 tile to 1, then for each unit (position floored through `Map::tile_of`) and each building (`construction::centre_tile` of its kind and `tile`, including sites and annexed Towns, stamped for their current owner) set every tile with `(x-cx)^2 + (y-cy)^2 <= r^2` to 2 where `r` is the kind's `vision_tiles`. Stamping is a maximum, so order does not matter; iterate in id order anyway. Integer arithmetic only.
3. Add the `visibility` field last in `State`, build it in `Sim::new`, call `visibility::step` as step 7, and add the sub-hash.
4. `SimView` (`ai_hook.rs`): `visibility(p) -> &[u8]`, `tile_state(p, tile) -> u8`, `units_visible_to(p)` (own units and others' units on state 2 tiles) and `buildings_known_to(p)` (own buildings and others' whose centre tile is state 1 or 2). In `facts.rs` change only the doc comment of `visible_enemies`, to cite ADR 0004.
5. New file `crates/sim/tests/m7.rs`, every name starting `fog_` so `cargo test -p sim fog` runs them all: `fog_grid_matches_vision_radii_for_a_fixture` (replay a scenario setup tick by tick; keep an independent expected grid built from the disc rule and the union of every earlier visible set; compare every 50 ticks), `fog_an_enemy_unit_outside_all_vision_is_hidden_in_simview`, `fog_explored_never_returns_to_unexplored`, `fog_restore_mid_match_matches_the_uninterrupted_run`, `fog_two_runs_are_identical`.
6. `just rerecord`; `just verify`; `just fixture-policy origin/main`.
7. Prove nothing else changed (P5 "same outcomes"): the three play-bots CSVs on `main` and on the branch must pass `scripts/same_outcomes.sh` with no output; `m5_first_match` and `scripted_match` end on the same tick with the same outcome.
8. Budget: warm `cargo test -p sim --profile ci` three times, each under 10 s; `sim-cli bench --units 400 --ticks 1200` and `--combat` before and after, rows into BUILD_TIMES. If the suite is over 10 s, stamp every N ticks through a `vision_stamp_every_ticks` field in `rules.ron` (default 4) inside this same bump.
