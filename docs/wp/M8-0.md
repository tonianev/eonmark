# M8-0: M9 readiness: two modifier targets and the data-only dry run

Size M · Risk medium · Lane S · Waits on: M7-5 (the faction plumbing), owner session O2 (PLAN)

## Why
ROADMAP M9 line 1 wants `git diff v0.1.0 -- crates/ | grep -c .` to print 0 for the Tidewater commit. The fixtures (they moved to the top-level `fixtures/` directory in the plan PR, with the tests made independent of the faction count) and the faction in the match setup (M7-5) are done. What remains: the Tidewater row's "lumber gather Mul 1100" and "Watchtower border push Add -1" ([../design/tech-and-ages.md](../design/tech-and-ages.md)) have no `StatPath` target.

## Anchors
- `crates/rules/src/modifiers.rs`: `StatPath`, `YieldCap`, `HarryingLevel`, `UnitSel`
- `crates/sim/src/tech.rs`: `town_radius`, `pub(crate) fn stat`
- `crates/sim/src/gather.rs`: `rate_per_worker`

- `crates/sim/src/annexation.rs`: `border_radius_tiles`

- `docs/design/tech-and-ages.md`: `Tidewater`

## Steps
1. Add `StatPath::GatherRate(String)` (a resource id) and `StatPath::BorderRadius(String)` (a building kind id) at the END of the enum, so existing rows serialise as before and `rules_hash` does not move. Validate the ids at load (an unknown id is an error naming the file), extend `StatPath::matches` and the worst-case validators (`all_rows` users: add a clamp for the radius, `1..=MAX_BORDER_RADIUS_TILES`, and a floor of 1 for the rate).
2. Apply them through `tech::stat`: in `gather.rs` where `g.rate_per_worker` is added (resolve per player and resource, base `rate_per_worker`, never below 1), and at every place a non-Town building's `border_radius_tiles` becomes a territory source. Enumerate those with `grep -n "border_radius_tiles" crates/sim/src/*.rs` and `grep -n "town_radius(" crates/sim/src/*.rs`: completion in `construction.rs`, a source moving owner in `annexation.rs`, and any recompute after a research. A Town keeps `tech::town_radius`.
3. With no rows in `data/`, nothing changes: every `.hash` stays byte-identical, `rules_hash` does not move, no bump is needed (prove it: `just verify`, `just fixture-policy origin/main`).
4. Tests (in `crates/sim/tests/`, each on a temp copy of `data/` with a row added): a lumber `GatherRate` row changes income by exactly the Mul; a `BorderRadius("watchtower") Add -1` row shrinks the Watchtower's source at completion and again after an annexation flip; a row naming an unknown id fails `Rules::load` naming the file.
5. Dry run, not committed (a scratch branch): add Tidewater's row (`YieldCap Mul 1250`, `GatherRate("lumber") Mul 1100`, `BorderRadius("watchtower") Add -1`) and a name string to `data/`, bump `rules_version`, `just rerecord`, `cargo test --workspace --profile ci`; then `git diff origin/main -- crates/ | grep -c .` must print 0 (it exits 1 when it prints 0: read the number) and `target/release/sim-cli play-bots --faction-a tidewater --faction-b freeholders --seeds 1..2` must run. Paste the outputs into the PR; delete the scratch branch.

## Verify
`scripts/quick_check.sh`; `just ci`; CI green.

## Done when
The dry run prints 0 and CI is green.

## Stop if
A target's semantics need a Rust decision the data cannot express (for example a rate below 1): write it up for the owner.
